# Languages (i18n)

[next-intl](https://next-intl.dev). Config: `src/config/site.ts` (`locales`, `rtlLocales`, `localeNames`) and `src/i18n/routing.ts`. Messages: `src/i18n/messages/<locale>.json`; `en.json` is the source of truth and its shape types every `t()` call.

## Languages

| Code | Language          | Direction | Body font                 | Heading font     |
| ---- | ----------------- | --------- | ------------------------- | ---------------- |
| `en` | English (default) | LTR       | Manrope                   | Fraunces         |
| `fa` | Persian           | RTL       | Vazirmatn                 | Vazirmatn        |
| `ar` | Arabic            | RTL       | IBM Plex Sans Arabic      | Amiri            |
| `de` | German            | LTR       | Manrope                   | Fraunces         |
| `ru` | Russian           | LTR       | Manrope (Cyrillic subset) | Playfair Display |

- **URLs:** the default language has no prefix (`/`, `/library`); the others are prefixed (`/fa`, `/ar/library`). `/en/…` redirects to `/…`. No automatic redirect by browser language: one URL = one language, which is what search engines and shared links expect.
- **SEO:** every public page gets `hreflang` alternates for all languages plus `x-default` (`src/lib/seo/metadata.ts`, `src/app/sitemap.ts`).
- **Fonts:** loaded with `next/font` in `src/app/[locale]/layout.tsx` and switched per script with `:lang(…)` rules in `src/styles/globals.css`. Only the Latin faces are preloaded; the others download only when a page actually contains that script (`unicode-range`), so English pages pay nothing for Arabic or Cyrillic. Fraunces has no Cyrillic, hence Playfair Display for Russian headings.
- **Emails** (invite, password reset, security notice) are sent in the recipient's language, subject line included (`emails.*` in the messages).

## Language picker

`src/components/layout/locale-switcher.tsx`:

- Header: a dropdown (Base UI `Menu`) of **real links**. Switching keeps the current page and query string (`/library?level=B1` → `/fa/library?level=B1`) and works without JavaScript.
- Mobile menu: the same list as a tappable grid (`LocaleList`).
- Each language is shown **only in its own name and script** (`siteConfig.localeNames`: English, فارسی, العربية, Deutsch, Русский). A second line with the name in the current language was tried and dropped as cluttered.
- Order in the picker = order of `locales` in `src/config/site.ts`.

## Adding a language

1. `src/config/site.ts`: add the code to `locales`, its own name to `localeNames`, and to `rtlLocales` if it's right-to-left.
2. Copy `src/i18n/messages/en.json` to `<code>.json` and translate it (rules below).
3. If its script isn't Latin, Arabic or Cyrillic, add fonts in `src/app/[locale]/layout.tsx` (`preload: false`, add the variable to `fontVariables`) and a `:lang(<code>)` block in `globals.css` setting `--font-body` and `--font-heading`.
4. Check every key and placeholder against English (script below), then `npm run check`.
5. Look at the landing page, the header (long words!) and an admin page in the new language, on a phone and on desktop.

The header measures itself (`header-bar.tsx`): if a language's section labels are too long for the bar, they move into the menu automatically, so no breakpoint tweaking is needed.

## Translation rules

- **Write it the way a native speaker would say it, not word for word.** The first Persian version was a literal translation and read badly; it was rewritten. Persian, German and Russian use the polite "you" (شما, Sie, вы).
- Keep placeholders exactly: `{name}`, `{count}`, `{title}`… and keep ICU plurals complete for the language: Arabic uses `zero/one/two/few/many/other`, Russian `one/few/many/other`, Persian only `other`.
- Brand and product names stay as they are (IELTS, CELTA, Google Meet, PDF). English idioms on the landing page stay in English; only their meaning is translated.
- Arabic text uses Western digits (that's what `Intl` produces for `ar`), Persian uses Persian digits in static text.
- Quotes per language: «…» (fa, ar, ru), „…“ (de), “…” (en).
- Next-intl treats `.` as nesting: **no dots inside keys**.

### Checking keys and placeholders

```bash
node -e '
const fs=require("fs"),dir="src/i18n/messages";
const flat=(o,p="")=>Object.entries(o).flatMap(([k,v])=>v&&typeof v==="object"?flat(v,p+k+"."):[[p+k,v]]);
const args=s=>[...String(s).matchAll(/\{(\w+)[,}]/g)].map(m=>m[1]).sort().join();
const en=Object.fromEntries(flat(JSON.parse(fs.readFileSync(dir+"/en.json"))));
for(const f of fs.readdirSync(dir).filter(f=>f!=="en.json")){
  const o=Object.fromEntries(flat(JSON.parse(fs.readFileSync(dir+"/"+f))));
  console.log(f,{missing:Object.keys(en).filter(k=>!(k in o)),extra:Object.keys(o).filter(k=>!(k in en)),placeholders:Object.keys(en).filter(k=>k in o&&args(en[k])!==args(o[k]))});
}'
```

All three lists should be empty for every file.
